# Operations

## Running Locally

The `.claude/skills` layer is not a runnable service. Skills are invoked interactively via Claude Code CLI. There is no local server, no port, and no startup command.

1. **Install Claude Code CLI** — ensure `claude` is available on `$PATH` (version requirements not stated in the repository).
2. **Clone the repository** — `git clone https://github.com/chrisrooney-max/legacy-migration.git`.
3. **Authenticate `gh` CLI** — run `gh auth login` if you intend to use `/create-epics`. Required scope: `repo`.
4. **Populate financial inputs** — edit `context/migration-inputs.md` with maintenance costs, engineering costs, call center costs, revenue, team capacity, and risk tolerance before running `/analyse` or `/assess-migration`.
5. **Open Claude Code in the repository directory** — skills in `.claude/skills/` are auto-registered as slash commands.
6. **Invoke a skill** — e.g. `/analyse /path/to/target/codebase` or `/document-system-overview /path/to/target/codebase`.

> ⚠️ Unclear: No minimum Claude Code CLI version is documented. No `package.json`, `Makefile`, or `requirements.txt` exists in this repository — setup steps above are inferred from CLAUDE.md and skill file content.

## Build & Deploy

- **Build steps:** None — this is a configuration-only repository with no compilation, transpilation, or bundling step.
- **Deployment process:** Skills are deployed by committing changes to the `main` branch of `chrisrooney-max/legacy-migration` and pulling the repository on the developer's local machine. CLAUDE.md states: "Always push changes to GitHub after completing analysis or creating epics."
- **Output artifact:** None for the skills layer itself. Analysis runs produce `documentationV{n}/` directories on the local file system.

## Common Issues

| Issue | Cause | Resolution |
|---|---|---|
| `migration-advisor` refuses to run | `context/migration-inputs.md` fields are blank or contain "Unknown" | Populate all financial fields in `context/migration-inputs.md` before invoking `/analyse` or `/assess-migration` |
| `/audit` audits `documentationV3/` instead of latest version | `doc-auditor` agent hardcodes `documentationV3/` as default target | Pass the correct directory as an explicit argument: `/audit documentationV{n}/` |
| Documents written to `index.md` not found by auditor | Individual skill output path (`<type>/index.md`) conflicts with `doc-auditor` expected path (`<type>-spec.md`) | Use the full `/analyse` pipeline which routes through `code-documenter` agent using `*-spec.md` naming, or rename files manually |
| `/create-epics` creates duplicate epics | Agent's natural language deduplication check is not exact-match | Run `gh issue list --label epic --repo chrisrooney-max/legacy-migration` before invoking; close duplicates manually |
| `gh label create` silently fails | `2>/dev/null \|\| true` suppresses all errors including permission errors | Verify `gh auth status` and confirm `repo` scope is granted before running `/create-epics` |

## Backup & Recovery

- **Backup process:** The repository is version-controlled in Git. All skill files and templates are recoverable from Git history. Generated documentation directories (`documentationV{n}/`) are pushed to GitHub per CLAUDE.md workflow convention.
- **Recovery steps:** `git checkout` any committed skill file or template to restore a previous version. Generated documents can be regenerated by re-running the relevant skill against the target codebase.
- **No database backup** — not applicable.
